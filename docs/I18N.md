# Native languages

Native screens support `en`, `de`, `es`, `ru` and `zh-CN`. Catalogs live in `locales/<language>/native.json`. `i18n/i18next.d.ts` derives strict translation keys from English. All catalogs ship in the app bundle; English supplies missing keys.

## Language flow

`i18n/index.ts` initializes i18next synchronously from the primary locale returned by expo-localization. German, Spanish and Russian regional variants use their corresponding catalog. `zh-Hans` variants and Chinese locales with the CN or SG region use Simplified Chinese. An explicit Traditional Chinese script, other Chinese regions, unspecified `zh`, and unsupported languages use English.

`i18n/preference.ts` restores the saved code from AsyncStorage in parallel with security initialization during boot. Native views initially use the device language (or English) and switch when a valid saved preference arrives. Language storage never gates screenshot protection, PIN-marker repair or splash release. A valid live change takes priority over an outstanding storage read. Changes take effect immediately, and writes are serialized so the latest change remains the saved preference. Storage failure leaves the current in-memory language active.

The Language row in the native Settings screen is where people choose a language in the app, because the wallet's Settings button opens that screen. `NativeBridge.setLanguage` changes native views at once, saves the code and sends `SET_LANGUAGE` with `{ language }` to the embedded wallet. While that choice waits for its echo, the bridge ignores other reports: they are a stale echo of an earlier choice or the wallet's catalog fallback.

Each time a web document activates and boot restoration has finished, the bridge syncs. With a saved language it sends `SET_LANGUAGE`, so a wallet that lost its storage or missed a choice catches up. With nothing saved, including after a failed storage read, it sends `REQUEST_LANGUAGE` and follows the wallet's answer, because a default must never overwrite a real choice. A document with a pending wipe gets neither.

The wallet reports with `LANGUAGE_CHANGED` with `{ language }` and the bridge's current `documentId` envelope on each change and in answer to `REQUEST_LANGUAGE`. `NativeBridge.handle` authenticates the document before accepting the exact five-code allowlist, so a report sent before the document handshake finishes is dropped; `REQUEST_LANGUAGE` covers that window. This message is allowed while locked, so lock and PIN screens match the wallet. Invalid payloads and unknown values cause no language or storage change. Origin, document-token and generation checks remain in the WebView boundary.

`useNativeLanguage` subscribes native views through react-i18next. The stable `t` function reads the current language at call time, keeping authentication and document lifecycle effects stable. PIN form validation and processing states retain typed keys. Known service and bridge errors are translated by `nativeMessage` at display time, including PIN attempt counts, lockout minutes and recovery instructions. Unknown external error details retain their original text.

iOS camera and Face ID permission descriptions are supplied through `locales/<language>/ios.json`. System permission sheets use the operating system's selected app language. App-drawn camera explanations, PIN forms and authentication prompt text use the synchronized native language. A system authentication sheet already in progress completes normally.

## Translation rules

Follow the web wallet's [glossary](https://github.com/DigitalGuards/myqrlwallet-frontend/blob/dev/src/locales/GLOSSARY.md), [translator notes](https://github.com/DigitalGuards/myqrlwallet-frontend/blob/dev/src/locales/en/_notes.json) and [translation guidance](https://github.com/DigitalGuards/myqrlwallet-frontend/blob/dev/docs/I18N.md).

- Preserve Quanta, QRL, QRL 2.0, MyQRLWallet, vendor names, addresses, recovery words, seeds, credentials and interpolated data.
- German uses neutral instructions, Spanish uses tú, and Russian uses вы. Use the glossary's terms for wallet, account, seed and recovery phrase.
- Keep security warnings complete: every affected wallet and earlier backup, permanent deletion, device authentication, required recovery steps, and old/new PIN ordering all carry meaning.
- Preserve English copy, including punctuation and credential scope. Native protocol error strings retain their API contract; translate them at the display boundary.
- Use complete messages and exact interpolation names. Russian count messages share `one`, `few`, `many` and `other` entries across all five catalogs for exact key parity.
- Screen labels, permission explanations, settings notifications copy, and bundled-wallet loading, retry and reinstall notices are covered. Push notification delivery and separate offline/update banners have no implementation in this wrapper.

## Validation

Run the CI commands documented in `.github/workflows/ci.yml`. Language tests cover device resolution, persistence races and failures, valid/invalid bridge messages, document authentication, key/placeholder parity, English fallback, Russian plurals, and live PIN-form translation without losing input or repeating submission. A permanent fake-timer startup probe checks the original security timings with slow, failed and pending language reads. Connection-date tests cover invalid timestamps and valid Date limits in all five languages, record retention through storage reload, and unchanged English date text. Invalid dates display the neutral placeholder `-`.
