# MyQRLWallet mobile 1.3.1

This update fixes Device Login setup being cancelled by the iOS authentication prompt's inactive state. The inactive grace covers the actual operating-system prompt. Ordinary inactivity, real backgrounding and interrupted authentication continue to revoke authorization. If a prompt settles while the app remains inactive, the normal lock grace is rechecked.

Wallet PIN fallback can read the existing device credential during its own native-initiated verification. The permission is limited to the exact current verification, authenticated web document, wallet generation and deadline. Credential creation stays blocked while locked, and delayed storage results are discarded after the verification or authorization changes.

Existing encrypted wallets, PINs, device credentials and earlier-profile backups are preserved. This update does not reset storage or create a replacement credential for an existing encrypted wallet. The coordinated hosted-wallet fix makes PIN verification read-only and removes a nested storage-queue wait that could stall verification and later wallet operations.

Regression coverage includes cold credential reads, stale and expired verification, concurrent attempts, real background interruption, prompt cancellation and errors, and Device Login setup across iOS inactive transitions. Installed-device acceptance remains separate from automated validation and signed build checks.
