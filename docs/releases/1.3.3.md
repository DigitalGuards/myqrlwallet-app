# MyQRLWallet 1.3.3

## Changes

- Coordinate the first Device Login attempt with the initial wallet document load and app foreground state.
- Keep successful authentication bound to the current wallet and document. Later reloads and real background interruptions continue to revoke stale results.
- Allow inline media playback for the trusted wallet view. The companion web update retries muted decorative playback on foreground return and provides a static fallback when playback is unavailable or reduced motion is preferred.
- Preserve existing wallet data, PIN fallback and Device Login settings. No wallet migration is required.

## Device acceptance

Update the existing installation and retain the wallet. Test a fully closed launch with Face ID, a launch followed by a slow foreground return, cancellation with manual retry, and Wallet PIN fallback. Confirm that unlocking requires one successful authentication and preserves the account.

Check Home video playback on first launch and after returning from Settings or another app. With reduced motion or blocked autoplay, the account card should remain readable with its static background. Device power-policy behavior requires physical iPhone verification.

Distribution for this update is iOS TestFlight. Android and public App Store promotion are separate release actions.
