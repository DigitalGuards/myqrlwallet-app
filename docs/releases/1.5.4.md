# MyQRLWallet 1.5.4

## Changes

- The bundled wallet is the November web release (frontend a22117b).
- Explorer links open ShorScan at shorscan.com, the explorer's new address. Links to zondscan.com from earlier versions still open.
- After a PIN unlock, dApp approvals and the wallet's own send, token and NFT screens check the request again before anything is signed or broadcast.
- A dApp request that fails answers the dApp with an error code that names the cause. Code 4001 now means only that you declined or dismissed the request.
- dApp connections use connect SDK 5.2.1.
- The wallet's Settings page has a new layout on the web. In the app, Settings opens the app's own settings screen, which is unchanged; the new web page shows only when a settings link from outside opens it.
- The wallet's page title and its notice for retired app versions name the App Store listing.
- Wallet data, PIN, Device Login settings, language and dApp pairings carry over from 1.5.3.
- The iPhone app is built with Xcode 27 and the iOS 27 SDK, which Apple requires from April 2027, and adopts the scene life cycle that iOS 27 needs.

## Device acceptance

Update the 1.5.3 store installation. Unlock with Face ID or fingerprint and with the wallet PIN, check the balance and history, send a small amount, and open an explorer link from the history: it opens shorscan.com. Walk every row of Settings, run Change PIN, switch the language and back, open the Address Book and Connected dApps and return. Pair shorscan.com/dapp-example and sign a message. On Android press Back on each wallet page and at Home. Settings shows Version 1.5.4 and Wallet build a22117b41e67 (bundled).

### Device acceptance for the Xcode 27 build (iPhone)

Run these on an iPhone with iOS 26 and, if one is available, on one with iOS 27.

1. Cold start from the home screen: no black screen, the splash goes away, Face ID or the PIN unlocks, the wallet shows. Do this three times in a row, closing the app from the app switcher each time.
2. Pairing link while the app is closed: close the app, open a `qrlconnect` pairing link from Safari or Notes. The app opens and the pairing request appears after unlock. Repeat with a link from https://qrlwallet.com/connect.
3. Pairing link while the app is running in the background: the same link opens the app and shows the request exactly once.
4. Open any other https://qrlwallet.com link (not /connect) with the app closed and then running: the app opens on the wallet and goes to that page after unlock.
5. Lock on return: put the app in the background for a few seconds, return, and it asks for Face ID or the PIN. Pull down the notification center or open the app switcher and release: the app must not lock in a loop or stay on the lock screen after a successful unlock.
6. Face ID prompt: start an unlock, cancel the prompt, retry; start Change PIN in Settings and complete the prompt. The app returns to the screen it was on.
7. Scan QR: the camera opens, a code is read, the camera closes. Deny the camera permission once and check the permission screen and Open Settings.
8. Screenshot protection: with Prevent Screenshots on, take a screenshot and start a screen recording on the wallet and on Settings: the content is hidden. Switch it off and on again.
9. Theme: switch Dark, Light and Same as the phone while the app is open, then flip the phone's appearance. Native screens and the wallet follow, and the status bar text stays readable. Background the app, change the phone's appearance, return: the right theme shows.
10. Rotate the phone on iPhone: the app stays upright. On iPad the app may rotate.
11. Send the app to the background in the middle of the wallet's own PIN entry and return: the wallet behaves as in 1.5.3.
