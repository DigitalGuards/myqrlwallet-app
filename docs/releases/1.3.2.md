# MyQRLWallet mobile 1.3.2

Device Login now allows a successful operating-system authentication to finish returning the app to the foreground. This bounded transition is tied to the current wallet, document and login attempt. The stored login PIN is read only after the app becomes active. Real backgrounding, an expired transition or a changed security context cancels the attempt.

Interrupted or cancelled login stays on a stable locked screen with manual retry. Choosing Use Wallet PIN immediately supersedes a pending Device Login result, and PIN fallback remains available during that transition. An ordinary return from the background can still authenticate a previously unlocked session once.

Existing encrypted wallets, login preferences, PINs and device credentials are preserved. This update does not reset wallet storage or require reinstalling the app.

Automated coverage combines the wallet screen, authentication service and lifecycle helpers to exercise delayed foreground return, timeout, cancellation, PIN fallback and stale authentication results. Physical-device Face ID acceptance remains a separate release check.
